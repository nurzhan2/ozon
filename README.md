# Автоматические отчёты OZON по 5 магазинам

Сервис собирает данные из **OZON Seller API** (аналитика, товары, остатки) и
**Performance API** (реклама) по пяти магазинам, формирует пять отчётов в
макетах заказчика и выкладывает их в Google Таблицы по расписанию.

- **08:00** — накопительная сводка, динамика день ко дню, качественные
  показатели по товарам, остатки по позициям
- **каждые 2 часа с 8:00 до 22:00** — промежуточный отчёт «сегодня на время T
  к вчера на время T»

Во всех отчётах исключаются артикулы с меткой **OUT**, а накопительные и
качественные строятся только по товарам, у которых есть остаток.

---

## Отчёты

| Команда | Что внутри | Образец заказчика |
|---|---|---|
| `cumulative` | Один лист, 5 магазинов блоками. Колонки: товар, дни, «Общий итог», «ср/день». Продажи в штуках | Отчет неделя_кол-во.xlsx |
| `dod` | Лист на магазин, три блока: вчера / позавчера / динамика. Колонки: Сумма, Количество, реклама, ДРР, Показы + «Итог» | динамика день ко дню.csv |
| `quality` | Лист на магазин. Свод «по аналитике» и блок на каждый товар: показы, клики, CTR, корзина, % корзины, купили (без отмен), отмен, место в поиске, оборот, реклама, ДРР % | скриншот «по аналитике» |
| `stocks` | Лист на магазин, строки артикул × кластер: Доступно, В заявках, В пути, Итог, прод 7д, среднее, потреб 30д, потреб 45д, на сколько дней хватит | Распред мазь 5 ядов.xlsx |
| `intraday` | Макет `dod`, но сегодня на время T к вчера на время T | тот же |

Оформление повторяет образцы: жёлтые шапки с красным жирным текстом, даты
`d-mmm`, трёхцветные шкалы, розовая подсветка нулевых остатков, зелёная —
закрытой потребности, формулы Excel в отчёте по остаткам.

Соответствие проверяется автоматически: `python verify_vs_samples.py` сравнивает
результат с эталонными файлами по заголовкам, цветам, форматам, формулам,
правилам подсветки и сортировке — 58 проверок.

## Развёртывание на Railway

Сервис — один постоянный процесс (`worker.py`), который сам держит оба
расписания. Отдельный cron не нужен.

### 1. Подключить репозиторий

В Railway: **New → Deploy from GitHub repo** → выбрать этот репозиторий.
Сборка пойдёт по `Dockerfile`, стартовая команда — из `railway.json`.

### 2. Постоянный диск

**Settings → Volumes → New Volume**, точка монтирования `/data`.

Это обязательно. В `/data/snapshots` лежат срезы для внутридневного сравнения;
без постоянного диска они стирались бы при каждом перезапуске, и отчёт
«сегодня на 12:00 к вчера на 12:00» было бы не с чем сравнивать.

### 3. Переменные окружения

**Variables** → задать по списку из `.env.example`. Значение `OZON_STORES`
удобно собрать скриптом:

```bash
cp local_config.example.py local_config.py    # вписать ключи
python make_env.py                            # печатает готовую строку
```

Минимальный набор: `OZON_STORES`, `GOOGLE_CREDENTIALS_JSON`, пять
`GOOGLE_SHEET_*`, `DATA_DIR=/data`.

### 4. Первый прогон

Чтобы не ждать 8 утра, поставьте `RUN_ON_START=1`, дождитесь в логах строки
«ИТОГ morning», проверьте ссылки на таблицы и верните `RUN_ON_START=0`.

В логах при старте видно часовой пояс, список магазинов, расписание и время
следующего запуска — по ним сразу понятно, что сервис жив.

## Google Таблицы

Отчёты обновляются в пяти постоянных таблицах: заказчик один раз сохраняет
ссылки и каждое утро видит свежие данные.

Подробная пошаговая настройка сервисного аккаунта — в **НАСТРОЙКА.md**.
Коротко: создать проект в Google Cloud, включить Drive API и Sheets API,
создать сервисный аккаунт и скачать JSON-ключ, создать пять пустых таблиц,
выдать сервисному аккаунту права Редактора и вписать их ID в переменные.

Проверка настройки:

```bash
python setup_gsheets.py
```

## Локальный запуск

```bash
pip install -r requirements.txt
cp local_config.example.py local_config.py     # вписать ключи

python diagnose.py           # проверить доступы к OZON
python run.py all            # отчёты 1-4
python run.py intraday       # промежуточный
python run.py all --no-upload           # только файлы, без Google
python run.py quality --store "ШТУЧКА"  # ограничить магазины
```

## Откуда берётся каждый показатель

| Колонка | Источник |
|---|---|
| Сумма / оборот | `revenue`, `/v1/analytics/data` |
| Количество / заказано | `ordered_units` |
| Показы | `hits_view` |
| клики | `session_view` |
| CTR | клики / показы |
| корзина | `hits_tocart` |
| % корзины | корзина / клики |
| купили (без отмен) | `ordered_units` − `cancellations` |
| отмен | `cancellations` |
| место в поиске | `position_category` (в своде — среднее по товарам) |
| реклама | Performance API, расход по товару за день |
| ДРР | реклама / сумма |
| Доступно / В заявках / В пути | кластерные остатки, при недоступности — склады |
| прод 7д | среднесуточные продажи OZON по кластеру × 7 |
| среднее, потреб 30д/45д, хватит дней | формулы Excel как в образце |

Формулы сверены на цифрах заказчика: ДРР `30312/190673 = 15,9%`,
CTR `3031/163696 = 1,85%`, % корзины `621/3031 = 20,5%`,
ДРР % `10422/70681 = 14,7%`.

## Что важно знать

**Внутридневное сравнение.** OZON отдаёт аналитику по дням, без разбивки по
часам. Поэтому «сегодня на 12:00 к вчера на 12:00» реализовано через снимки:
каждый запуск сохраняет срез накопленных за день значений, на следующий день
сравнение идёт с вчерашним снимком того же часа. В первый день снимков ещё нет
— сравнение идёт с полным вчерашним днём, в шапке блока стоит пометка.

**Остатки по кластерам.** Основной метод — `/v1/analytics/manage/stocks`. Если
он на аккаунте недоступен, код автоматически переходит на
`/v2/analytics/stock_on_warehouses`, и в колонке «Кластер» будет склад.

**Лимиты OZON.** Seller API держит 2 запроса в секунду на клиента — в коде
стоит общий ограничитель частоты. Performance API принимает не больше 10
кампаний в одном запросе статистики — запросы идут пачками по 10.

**Новые магазины.** Добавляются одним блоком в `OZON_STORES` — переписывать
ничего не нужно, отчёты подхватят их сами.

**Версии методов API.** OZON периодически меняет эндпоинты и имена полей. Они
вынесены в начало методов в `ozon/seller_api.py` и `ozon/performance_api.py`.

## Структура

```
├─ worker.py               планировщик для Railway (точка входа сервиса)
├─ run.py                  ручной запуск отчётов
├─ diagnose.py             проверка доступов к OZON
├─ probe.py                поиск Client-Id, если он неизвестен
├─ setup_gsheets.py        проверка доступа к Google Таблицам
├─ make_env.py             сборка строки OZON_STORES для Railway
├─ config.py               конфигурация из переменных окружения
├─ Dockerfile / railway.json
└─ ozon/
   ├─ seller_api.py        аналитика, товары, остатки, кластеры
   ├─ performance_api.py   реклама, расход по товарам
   ├─ collector.py         сбор данных по магазину
   ├─ processing.py        фильтр OUT, подневная структура, KPI
   ├─ reports.py           пять генераторов Excel
   ├─ excel.py             оформление под образцы
   ├─ gsheets.py           выгрузка в Google
   ├─ snapshots.py         снимки для внутридневного сравнения
   └─ dates.py             даты в московском времени
```
