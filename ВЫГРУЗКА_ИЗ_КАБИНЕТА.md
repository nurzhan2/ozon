# Выгрузка из кабинета OZON: что нужно и куда класть

В общую папку кладём **два разных файла**. Оба нужны потому, что этих данных
нет в API ни в одном методе — их отдают только в кабинете.

| Файл | Что закрывает | Как часто |
|---|---|---|
| **1. Аналитика по товарам** | «корзина», «% корзины», «показы», настоящие «клики» в отчёте 3 | один файл в день |
| **2. Выгрузка заказов** | «прод 7д» по **кластеру доставки** в отчёте 4 «Остатки» | один файл, обновлять раз в неделю |

Программа сама разбирается, что ей дали: тип определяется по шапке файла,
а не по имени и не по отдельной папке. Кладите в подпапку своего магазина оба.

Если файлов не положить, отчёты всё равно соберутся: в отчёте 3 строки
останутся пустыми с пояснением под таблицей, а «прод 7д» в отчёте 4
посчитается прикидкой (как именно — в конце документа).

---

## Файл 1. Аналитика по товарам

В кабинете продавца: **Аналитика → Графики**.

**Показатели:** «Уникальные посетители, всего», «Уникальные посетители
с просмотром карточки товара», «Конверсия в корзину из карточки товара»,
«Позиция в поиске и каталоге». Если в списке есть «В корзину» в штуках —
отметьте и её, будет точнее.

Ровно этот набор и был в первой присланной выгрузке, менять его не нужно.

**Группировка:** «Только товары».

**Период: ОДИН ДЕНЬ.** Вчерашний.

Это главное и единственное, что важно. Конструктор отчётов в кабинете не
умеет разбивать данные по дням — в настройке группировок есть только товары,
бренды и категории. Поэтому выгрузка за неделю приходит одной строкой на
товар за всю неделю, и разложить её по дням невозможно.

Значит: один файл — один день. Ставите период «вчера», скачиваете, и завтра
то же самое.

**Имя файла: дата этого дня.** Например `2026-08-08.xlsx`. Программа берёт
день именно из имени, больше его в файле взять негде. Подойдут и
`08.08.2026.xlsx`, и `20260808.xlsx`.

**Формат:** XLSX или CSV — оба подходят.

Первый раз, чтобы заполнить текущий месяц, придётся выгрузить по файлу на
каждый прошедший день. Дальше — один файл в день, минута.

---

## Файл 2. Выгрузка заказов — продажи по кластеру доставки

Это тот самый файл, из которого вы сами строите сводную «продажи 7 дней,
убрала отмены». Ничего нового готовить не надо: положите его как есть.

Зачем он. В отчёте 4 колонка **«прод 7д»** должна считаться по кластеру
**доставки** — куда товар уехал. В API такого разреза нет вообще: метод
остатков знает только кластер, где товар **лежит**, то есть отгрузки. Без
этого файла «прод 7д» приходится раскладывать по кластерам пропорцией, а
это прикидка, а не факт.

**Откуда взять:** кабинет продавца → **FBO → Заказы → Скачать отчёт**
(или тот же файл, из которого делается ваша сводная).

**Какие колонки обязательны** — они и так есть в стандартной выгрузке:

- **«Принят в обработку»** — по этой дате считается неделя;
- **«Кластер доставки»** — по нему идёт группировка (не «Кластер отгрузки»,
  он в файле рядом и его легко перепутать — программа берёт именно доставку);
- **«Артикул»**;
- **«Количество»**;
- **«Статус»** — нужен, чтобы выкинуть отмены.

Лишние колонки не мешают, порядок значения не имеет, лист внутри книги
ищется по шапке — рабочую книгу на десяток листов класть можно.

**Отмены убирать не надо.** Программа сама пропускает строки со статусом,
в котором есть «отмен», и пишет в лог, сколько выкинула. Если вы уже убрали
их руками — тоже ничего страшного.

**Период — в отличие от файла 1, здесь он свободный.** В выгрузке заказов
есть колонка с датой, поэтому один файл может покрывать сколько угодно дней.
Берите с запасом, недели за две: в расчёт всё равно попадут только последние
7 дней, а лишние даты просто не понадобятся.

**Имя файла — любое.** Дата в имени тут не нужна, она есть внутри.

**Как часто обновлять.** Раз в неделю достаточно. Чем свежее файл, тем
точнее «прод 7д»: если файл недельной давности, окно в отчёте частично
уедет в дни, которых в нём нет, и продажи занизятся.

## Куда класть

В общей папке Google Диска (ссылку пришлём отдельно) лежит по подпапке на
каждый магазин:

```
Выгрузки OZON/
├── СЕКРЕТЫ КРАСОТЫ/
├── БЬЮТИФУЛ/
├── ДАЙМОНД/
├── ЛИНИЯ МЕЧТЫ/
└── ШТУЧКА/
```

Оба файла — и дневную аналитику, и заказы — перетащите в подпапку своего
магазина. Раскладывать по разным папкам не нужно, программа различает их
по шапке.

Старые файлы удалять не нужно — программа читает их все и собирает из них
период. Имена подпапок менять нельзя: по ним определяется магазин.

---

## Когда класть

До начала утреннего сбора. Час сбора задаётся переменными `MORNING_HOUR`
и `MORNING_MINUTE`; он выставлен так, чтобы идти уже после вашей выгрузки.

Если аналитика окажется вчерашней или позавчерашней, ничего страшного не
случится: заполнятся те дни, которые в ней есть, остальные останутся пустыми.
Заказы можно обновлять и реже — раз в неделю.

---

## Как проверить, что сработало

В логе сбора появятся строки вида:

```
[СЕКРЕТЫ КРАСОТЫ] выгрузка кабинета с Диска: файлов 8, дней 8, товаров 14
[СЕКРЕТЫ КРАСОТЫ] заказы.xlsx: пропущено отменённых строк: 143
[СЕКРЕТЫ КРАСОТЫ] продажи по кластеру доставки из выгрузки заказов: товаров 13
```

Первая — про аналитику, вторая и третья — про заказы.

А в отчёте 3 строки «показы», «клики», «корзина» и «% корзины» заполнятся, и
из-под таблицы пропадёт блок «Почему эти строки пустые». Заодно из названий
строк исчезнет пометка «(реклама)»: пока выгрузки нет, клики берутся только из
рекламного отчёта, а с ней — настоящие, все.

Если что-то пошло не так, в логе будет сказано, что именно: не нашлась
подпапка, не разобралась шапка файла или в имени файла нет даты.

## Что будет с «прод 7д», если заказов не положить

Отчёт 4 соберётся в любом случае, но колонка посчитается тем, что есть под
рукой, — в таком порядке:

1. **Есть выгрузка заказов** — берутся настоящие штуки по кластеру доставки
   за 7 дней. Это то, что нужно.
2. **Выгрузки нет** — берутся реальные продажи товара за неделю по магазину
   и раскладываются по кластерам пропорционально их доле в продажах
   (`ads_cluster` из API). Сумма верная, разбивка приблизительная — и она
   по кластеру **отгрузки**, а не доставки.
3. **Продажи за неделю недоступны** — берётся среднесуточный темп кластера
   за 28 дней, умноженный на 7.
4. **OZON не дал продаж по кластерам вовсе** — деление по доле в остатках.
   Самый грубый вариант, но лучше, чем нули во всех строках.

## Настройка со стороны проекта (делается один раз)

1. Создать на Google Диске папку с подпапками по именам магазинов —
   в точности как в `OZON_STORES`.
2. Открыть к папке доступ сервисному аккаунту (его почта печатается при
   запуске выгрузки в Google Таблицы) — достаточно прав «Читатель».
3. Тому, кто будет класть файлы, дать права «Редактор».
4. Скопировать ID папки из адресной строки:
   `https://drive.google.com/drive/folders/`**`1AbC...XyZ`** — нужен
   выделенный кусок.
5. Прописать его в Railway → Variables:

```
GOOGLE_IMPORT_FOLDER=1AbC...XyZ
```

Локально файлы можно класть и без Диска — в `DATA_DIR/import/<Магазин>/`.
Диск проверяется первым, локальная папка — запасной вариант.
